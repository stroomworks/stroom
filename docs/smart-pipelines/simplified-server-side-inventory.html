Shapeshifter AI: simplified server-side inventory

Branch ai_translations · 9 November 2026 · The server side as it would be once every option in the simplification options document is implemented. Client code is out of scope.

This describes a proposal, not today's code. It's the counterpart of the server-side inventory, which records the code as it stands. It assumes all of the simplification options are implemented:

  • A: review by default, and one promotion path for both modes
  • B: a fixed learning recipe
  • C: no provisional bindings
  • D: a smaller Supervisor
  • E: prompts in code
  • F: unused parts removed
  • i–iv: one execution path, fewer storage interfaces, services instead of one central class, test code out of the product
  • the safety controls the options document requires before any feed runs automatically

Counts taken from the current code are exact. Projected sizes are marked ≈ and are estimates. Names of new classes, settings and permissions are illustrative until the work is designed.

3. How it runs

The runtime path keeps its shape. Four changes are visible here:

  • Each kind of work belongs to one service.
  • Candidates are run by the real pipeline.
  • Every promotion goes through a draft.
  • Every model call passes the spend breaker and rate limit first.

Compared with today: no provisional branch, no in-place rewrite, no improve call inside a web request, and the parallel parser runners are gone. Supervisor actions go through a service rather than straight to the engine.

10. Package structure

Packages are named for what they do, and only depend downwards. Today, five packages form one cycle of about 15,000 lines, and doc and element form another. In the target state an architecture test (ArchUnit or similar) fails the build if a dependency points the wrong way.

Arrows mean "depends on". pipeline, doc and model in -impl provide the production bindings of ports (candidate runner, documents, advisor) and are wired by Guice. The services see only the port interfaces.

13. Still open

The simplification options don't address these. They still need decisions or work:

  1. Sending log data to the model. Samples go to the model unredacted (A146). Someone must own which feeds' data may go to which model.
  2. Turn text retention. shapeshifter_turn stores every question and answer, and questions contain samples of the feed's data. Retention prunes them (attemptRetention). Check that the period suits the most sensitive feed, and that the table is protected accordingly.
  3. Drift the system can't see. Lines a parser drops while serving are reported but never judged (ISSUES 2), so some format changes go unnoticed. This matters more on automatic feeds.
  4. stroom-ai-api. It still mixes model access with Ask Stroom's chat storage and exposes langchain4j types. Shapeshifter is insulated from this by its Advisor port. Fixing it is separate work, on a module that's already on master.
  5. Engine domain model. Decide whether -engine gets its own records, mapped to the shared DTOs in -impl, so the client contract and the engine can change independently (finding 5).
  6. Scale. The Supervisor's backlog and learners lists still group or page parts of the data in memory (ISSUES 11). Watch this in the real-scale trial.
  7. Release numbering. The migration version (V08_00_00_001) must match the release this ships in.
