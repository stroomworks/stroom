# Pilot results: case 01 (firewall), 4 November 2026

Six runs of Claude Code sub-agents (Haiku, Sonnet, Opus, each on arm A and arm B) against `case-01-firewall`.
Each stylesheet, its output, its messages and its golden-event result are in the `run-*` folders beside this file.
Scored with `tools/run-checks.sh`.

**Read this first.** One run per cell, one small case, and a sub-agent harness inside the repository's environment.
Isolation was by instruction only (each agent was told to stay in its own directory), and I cannot show that none
looked elsewhere. I wrote the case and the golden events, and I played the user in arm B. The model names are Claude
Code aliases; I could not see which versions they are. Treat everything below as indicative.

## What the pilot shows

1. **Every run produced a working, schema-valid translation, including Haiku.** On this case the schema validator
   alone could not separate a good run from a poor one. The golden events separated exactly one: run 5.
2. **The one failure was an unasked judgement call.** Opus, one-shot, kept the record with `src=10.0.0.999`, moved the
   bad value into a `Data` element, and said so in its assumptions. That is a defensible choice, and it is
   schema-valid, but it is not what the user intended (decision D7). **All three arm B runs asked about D7 and got it
   right.** This is the case that supports the "system asks" design (§2.4 of the design note): the golden event is
   how the user's intent is captured, and a one-shot run cannot know it.
3. **The swap-risk trap was not tested.** No model asked about D2, and every model got it right, because the fields are
   named `src` and `dst`. The case did not make the ambiguity real. Case 2 should use positional fields with no names
   (for example a CSV row `10.0.0.5,203.0.113.9`), where the swap really is ambiguous.
4. **No model reported a dropped record unless told to.** In arm A, none of the three raised a message for the
   comment, garbled or bad-address records. Stroom users depend on errors in the error stream. This is a prompt and
   product point: the design's honest-labelling requirement (§6.7) needs the system to ask for, or insist on,
   reporting.
5. **Invented constants are the norm.** Every model made up `System/Environment` (Production or Unknown) and the
   `TypeId`. All said so in their reports. Haiku, one-shot and asked, used "Unknown" and invited correction. The
   schema makes `System/Environment` mandatory, so the system has to ask or
   configure it. Only two of the three arm B models asked.
6. **Haiku's weakness did not show on this case.** It matched Opus and Sonnet on the golden events. That says the
   case is easy, not that a weaker model is fine. It is not evidence about an on-premises model.
7. **Honest reporting held up.** I did not see a report claim a check that was not done, and every report listed its
   assumptions. I checked the schema and golden claims independently with the scripts, and they were true.
8. **Rough cost data does exist.** The harness reported total tokens per sub-agent (not split into input and
   output): about 83k, 94k, 61k, 66k, 63k and 64k for runs 1 to 6, and 25 to 154 seconds each. That is real but
   coarse, and it gives no dollar figure on a subscription.

## What to change before the next case

- Add a case where **swap-risk is real** (positional fields), and one where the **record boundary** is hard (multi-line).
- Make **reporting a dropped record** one of the golden checks, not just a message the user must remember to request.
- Add the **Data Splitter half**, which this case did not test.
- Run each cell **more than once**, and run the clean-directory protocol in `README.md` by hand for at least one cell, to
  check the isolation.
