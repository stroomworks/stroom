* Bug : Stop destroying fragments that are waiting to be merged, or whose merge failed. The merge processor deleted the entire contents of its merging directory at startup, while the source zip had already been deleted once the fragment was queued — so a fragment retained after a failed merge, which the operations guide told administrators would be retried once the cause was fixed, was in fact lost at the next restart, silently leaving that node short of a stream's data. Fragments now survive a restart and are requeued, and the synchronous path retains the source zip when a fragment in it fails.
