* Bug : With `stroom.query.optimiser.mode` set to `ON`, a `where` clause with an inclusive upper time bound (`<=`, or `between`'s upper end) silently dropped rows falling exactly on that bound, because the derived scan range was applied at search time as a strict `<`. The derived range is now widened to its exact exclusive equivalent, so it prunes which shards are searched without ever changing which rows match.
